# Mini NPU Simulator (MAC 연산 기반 패턴 판별 계산기)

AI(인공신경망)와 NPU(Neural Processing Unit)의 핵심 연산인 **MAC(Multiply-Accumulate, 곱셈-누적 덧셈)** 연산 원리를 외부 라이브러리(NumPy 등) 없이 순수 Python 표준 라이브러리만으로 구현한 콘솔 시뮬레이터입니다.

---

## 1. 프로젝트 구조 및 실행 방법

### 파일 구성
- `main.py`: Mini NPU 시뮬레이터 메인 실행 파일 (모드 1, 모드 2, 보너스 패턴 생성기 및 1D 메모리 최적화 포함)
- `data.json`: 크기별(`5×5`, `13×13`, `25×25`) 필터(`cross`, `x`) 및 테스트 패턴 데이터셋
- `README.md`: 실행 가이드, 구현 요약 및 결과 리포트(실패 원인 분석 + $O(N^2)$ 시간 복잡도 분석)

### 개발 및 실행 환경
- **Python 버전**: Python 3.8 이상
- **의존성**: 외부 라이브러리 미사용 (표준 라이브러리 `json`, `time`, `os`, `re`, `sys`, `typing`만 사용)

### 실행 명령어
`main.py`와 `data.json`이 위치한 디렉터리에서 아래 명령어를 실행합니다.

```bash
python main.py
```

실행 후 콘솔 메뉴에서 원하는 모드를 선택합니다:
1. **`1` (사용자 입력 3×3 모드)**:
   - `3×3` 필터 A, 필터 B, 입력 패턴을 한 줄씩(공백으로 구분된 3개의 숫자) 입력합니다.
   - 행/열 개수가 맞지 않거나 숫자가 아닌 값이 입력되면 오류 안내 문구를 출력하고 해당 줄의 재입력을 유도합니다.
   - 두 필터의 MAC 점수, 10회 반복 평균 연산 시간(ms), 판정 결과(`A` / `B` / `판정 불가`) 및 `3×3` 성능 분석 표를 출력합니다.
2. **`2` (`data.json` 분석 모드)**:
   - 현재 작업 디렉터리(또는 `main.py`와 동일한 폴더)의 `data.json`을 읽어 `5×5`, `13×13`, `25×25` 필터와 테스트 패턴을 일괄 검증·판정합니다.
   - 케이스별 `Cross` 점수, `X` 점수, 판정(`Cross` / `X` / `UNDECIDED`), `expected` 비교 결과(`PASS` / `FAIL`), 크기별 성능 분석 표, 전체 결과 요약을 출력합니다.
3. **`3` (보너스: `N×N` 패턴 생성기 및 시뮬레이션 모드)**:
   - 사용자가 입력한 임의의 크기 $N$($N \ge 3$)에 대해 $N \times N$ 십자가(`Cross`) 및 `X` 패턴을 자동 생성하고 MAC 연산 및 2D vs 1D 성능 비교를 수행합니다.

## 2. 구현 요약

### 2.1 MAC(Multiply-Accumulate) 연산과 NPU의 원리
- 컴퓨터는 이미지를 시각적 형태가 아닌 2차원 숫자 배열로 처리하며, 특정 형태를 판별하기 위한 기준 배열을 **필터(Filter)**라고 합니다.
- 입력 패턴 $P$와 필터 $F$의 유사도(점수)는 같은 위치 $(r, c)$의 원소끼리 곱하고 모두 더하는 **MAC 연산**으로 계산합니다:
  $$\text{Score} = \sum_{r=0}^{N-1} \sum_{c=0}^{N-1} P[r][c] \times F[r][c]$$
- `main.py`의 `Grid2D` 클래스는 $N \times N$ 2차원 배열을 캡슐화하여 `set(row, col, val)`과 `get(row, col)`로 특정 위치 값을 안전하게 저장·조회하며, `mac_calculate_2d()` 함수가 이중 반복문으로 MAC 점수를 계산합니다.

### 2.2 라벨 정규화 (Label Normalization)
- 외부 데이터(`data.json`)에서는 필터 키와 정답(`expected`) 라벨이 작성자나 수집 경로에 따라 `'+'`, `'cross'`, `'Cross'`, `'x'`, `'X'` 등으로 혼용될 수 있습니다.
- 프로그램 내부에서 라벨 표현이 통일되지 않으면 MAC 연산 로직이 정확하더라도 단순 문자열 비교(`'Cross' != '+'`)에서 오답(`FAIL`)이 발생합니다.
- 이를 방지하기 위해 `normalize_label()` 함수를 구현하여 모든 입력 라벨을 내부 표준 라벨 2가지(`Cross`, `X`)로 정규화한 뒤 출력 및 `PASS`/`FAIL` 판정에 사용합니다:
  - `expected` 값: `'+'`, `'cross'`, `'Cross'` $\rightarrow$ **`Cross`** / `'x'`, `'X'` $\rightarrow$ **`X`**
  - `filter` 키: `'cross'`, `'+'` $\rightarrow$ **`Cross`** / `'x'` $\rightarrow$ **`X`**

### 2.3 허용오차(Epsilon) 기반 점수 비교 정책
- 컴퓨터의 IEEE 754 배정밀도 부동소수점(`float`) 연산은 이진수 근사 표현의 한계로 인해 미세한 반올림 오차(예: `0.3 + 0.3 + 0.3 = 0.8999999999999999`, `0.45 + 0.45 = 0.9000000000000000`)가 발생합니다.
- 단순 대소 비교(`score_a > score_b`)를 사용하면 수학적으로 동일한 두 점수($0.9 = 0.9$)를 서로 다른 값으로 오판하여 특정 필터의 승리로 잘못 판정하게 됩니다.
- 따라서 허용오차 $\epsilon = 10^{-9}$ (`EPSILON = 1e-9`) 정책을 적용한 `judge_scores()`를 구현하였습니다:
  - $|\text{Score}_A - \text{Score}_B| < 10^{-9}$ 이면 부동소수점 오차 범위 내의 **동점(`UNDECIDED` / `판정 불가`)**으로 처리합니다.
  - 차이가 $10^{-9}$ 이상일 때만 더 큰 점수를 가진 필터(`Cross` 또는 `X`)로 판정합니다.

### 2.4 보너스 과제 구현
1. **시뮬레이터 메모리 접근 최적화 (`to_1d_list`, `mac_calculate_1d`)**:
   - 2차원 리스트(`grid[r][c]`)는 행 리스트 참조 후 열 원소를 참조하는 2단계 포인터 역참조와 이중 루프 오버헤드가 발생합니다.
   - 이를 길이 $N^2$의 1차원 연속 배열로 평탄화(`flatten_2d`)하여 단일 루프(`for i in range(N*N)`)로 접근 패턴을 단순화하고, 동일 입력·반복 조건에서 2D와 1D의 평균 연산 시간을 비교 출력합니다.
2. **패턴 생성기 (`generate_cross_pattern`, `generate_x_pattern`)**:
   - 임의의 크기 $N$ 입력 시 $N \times N$ 십자가(`Cross`)와 `X` 패턴을 자동 생성하여 성능 측정(`3×3`, `5×5`, `13×13`, `25×25`) 및 보너스 모드 3에서 재활용합니다.

## 3. 결과 리포트

### 3.1 실패 원인 분석 (데이터/스키마 vs 로직 vs 수치 비교 진단)

`data.json`의 총 8개 테스트 케이스를 실행한 결과는 **총 테스트 8개 / 통과(PASS) 7개 / 실패(FAIL) 1개**입니다. 실패 케이스 및 잠재적 오류 원인을 **① 데이터/스키마 문제**, **② 로직 문제**, **③ 수치 비교(부동소수점) 문제**의 3가지 관점으로 분리하여 진단한 결과는 다음과 같습니다.

1. **`size_13_1` 실패 원인 — 수치 비교 및 동점 처리 정책에 의한 정상적 FAIL**:
   - `size_13_1` 패턴에서 `Cross` 필터만의 활성 위치에는 `0.45`씩 2개($0.45 \times 2 = 0.9$), `X` 필터만의 활성 위치에는 `0.3`씩 3개($0.3 \times 3 = 0.9$)가 배치되어 있습니다.
   - 수학적으로 두 필터의 MAC 점수는 모두 정확히 $0.9$로 동점입니다. 그러나 Python의 IEEE 754 부동소수점 누적 덧셈 결과는 각각 다음과 같이 계산됩니다:
     - `Cross 점수`: `0.45 + 0.45 = 0.9000000000000000`
     - `X 점수`: `0.3 + 0.3 + 0.3 = 0.8999999999999999`
   - 두 점수의 차이는 $|0.9000000000000000 - 0.8999999999999999| \approx 1.11 \times 10^{-16}$으로, 만약 허용오차(`epsilon`) 정책 없이 `score_cross > score_x`로 비교했다면 부동소수점 오차 때문에 `Cross`로 잘못 판정되었을 것입니다.
   - 본 시뮬레이터는 $|\text{Cross} - \text{X}| < 10^{-9}$ 허용오차 기준에 따라 두 점수를 **동점(`UNDECIDED`)**으로 정확히 판정하였고, `expected: X`와 일치하지 않으므로 동점 처리 규칙에 따라 `FAIL`로 분류하였습니다.
2. **나머지 7개 케이스(`size_5_1`~`size_5_3`, `size_13_2`~`size_13_3`, `size_25_1`~`size_25_2`)가 PASS가 된 이유 — 라벨 정규화 효과**:
   - `data.json` 내부에는 필터 키가 소문자(`"cross"`, `"x"`)로 저장되어 있고, 각 패턴의 `expected` 값은 기호(`"+"`), 소문자(`"x"`), 대소문자 혼합(`"Cross"`) 등으로 불규칙하게 정의되어 있습니다.
   - `normalize_label()`을 통해 모든 필터 키와 `expected` 값을 표준 라벨(`Cross`, `X`)로 정규화했기 때문에 데이터 표기 불일치로 인한 실패가 0건이 되었습니다.
3. **데이터/스키마 및 크기 불일치 방어 검증**:
   - 패턴 키(`size_{N}_{idx}`)에서 추출한 필터 크기 $N \times N$과 실제 `input` 배열의 행·열 크기가 다른 경우(예: `size_5_*`에 `3×3` 패턴이 입력된 경우) 또는 지원하지 않는 라벨이 들어온 경우, `validate_2d_numeric_matrix()`가 이를 사전 감지하여 프로그램을 중단시키지 않고 해당 케이스만 구체적인 사유(`크기 불일치 (필터 5×5 vs 입력 3×3)`)와 함께 `FAIL`로 격리 처리함을 검증하였습니다.

### 3.2 성능 분석 및 시간 복잡도 $O(N^2)$ 근거

크기별(`3×3`, `5×5`, `13×13`, `25×25`) MAC 연산을 I/O 시간을 제외하고 순수 연산 구간만 10회 반복 측정한 평균 시간과 연산 횟수는 아래 표와 같습니다.

| 크기 ($N \times N$) | 연산 횟수 ($N^2$) | 2D 평균 시간 (ms) | 1D 평균 시간 (ms, 보너스) | $N=3$ 대비 연산량 비율 | $N=3$ 대비 2D 시간 비율 |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **3×3** | $9$ | `0.0013 ms` | `0.0010 ms` | $1.0\times$ | $1.0\times$ |
| **5×5** | $25$ | `0.0021 ms` | `0.0013 ms` | $2.8\times$ | $1.6\times$ |
| **13×13** | $169$ | `0.0092 ms` | `0.0076 ms` | $18.8\times$ | $7.1\times$ |
| **25×25** | $625$ | `0.0304 ms` | `0.0281 ms` | $69.4\times$ | $23.4\times$ |

*(※ 측정 시간은 실행 시점의 CPU 클럭 및 OS 스케줄링 상태에 따라 미세하게 달라질 수 있으나, 크기 증가에 따른 비례 추세는 일관되게 유지됩니다.)*

#### 시간 복잡도 $O(N^2)$ 증명 및 해석
1. **이론적 연산 횟수 근거**:
   - $N \times N$ 크기의 패턴과 필터에 대한 MAC 연산은 외부 루프가 행($r = 0 \dots N-1$)을 $N$번 순회하고, 내부 루프가 열($c = 0 \dots N-1$)을 $N$번 순회합니다.
   - 가장 안쪽 루프에서 곱셈 1회와 누적 덧셈 1회(상수 시간 $O(1)$)가 총 $N \times N = N^2$번 실행되므로, 전체 시간 복잡도는 다음과 같습니다:
     $$T(N) = \sum_{r=0}^{N-1} \sum_{c=0}^{N-1} O(1) = N \times N \times O(1) = O(N^2)$$
2. **실측 데이터와의 연결**:
   - 패턴의 한 변 크기 $N$이 $5 \rightarrow 13 \rightarrow 25$로 증가할 때, $N$ 자체는 $1\text{배} \rightarrow 2.6\text{배} \rightarrow 5\text{배}$ 증가하지만, 실제 MAC 연산 횟수($N^2$)는 $25 \rightarrow 169(\text{약 } 6.76\text{배}) \rightarrow 625(25\text{배})$로 **제곱($N^2$)에 비례하여 급증**합니다.
   - 실측된 2D 평균 연산 시간 역시 `5×5`(`0.0021 ms`)에서 `13×13`(`0.0092 ms`, 약 $4.4$배), `25×25`(`0.0304 ms`, 약 $14.5$배)로 $N$의 증가폭보다 훨씬 가파르게($N^2$ 추세로) 증가함을 확인할 수 있습니다. (`3×3`, `5×5`처럼 매우 작은 크기에서는 함수 호출 고정 오버헤드 비중이 일부 포함되고, $N \ge 13$부터는 루프 연산 시간이 지배적이 되어 $N^2$ 비례 관계가 더욱 뚜렷하게 나타납니다.)
3. **2D vs 1D 메모리 접근 최적화 및 NPU의 필요성**:
   - 2차원 배열(`N×N`)을 길이 $N^2$의 1차원 배열로 변환(`mac_calculate_1d`)하면 이중 루프 분기 비용과 2단계 리스트 참조(`pattern[r][c]`)가 1단계 참조(`pattern_1d[i]`)로 줄어들어 `3×3`~`13×13` 구간에서 약 `17% ~ 36%`의 실행 시간 단축 효과를 얻었습니다.
   - 그러나 1차원 최적화를 적용하더라도 직렬 CPU에서는 연산 횟수 $N^2$ 자체를 줄일 수 없으므로 여전히 시간 복잡도는 $O(N^2)$입니다. 실제 딥러닝 모델처럼 수백$\times$수백 크기의 필터 수천 개를 처리할 때는 수억 번의 MAC 연산이 필요하므로, 이를 단일 사이클에 수천 개씩 병렬로 동시 처리할 수 있는 전용 하드웨어인 **NPU(Neural Processing Unit)**가 필수적임을 본 시뮬레이션을 통해 확인할 수 있습니다.
